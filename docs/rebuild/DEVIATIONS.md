图片大小过滤的本地实现决定：沿用现有 CDP Fetch owner，按原 UI 的 KB 转字节，超限阻止，未知/压缩长度通过有界流读取，最多 8192 KB，浏览器内串行读取并限制队列。不会新增另一个互相覆盖的 Fetch owner，也不替换原请求头/字体/worker 流程。此功能只对 Chromium 的网络图片响应生效；data/blob 和 Firefox 私有内核等价能力尚未确认，Firefox 对正阈值应明确报不支持，不能只保存后假装生效。完成前不记通过。

模板商城的本地化补充决定：原页面保持原卡片/获取交互，目录改为本机已启用 Skill 的真实元数据，不返回远程商品或虚构脚本。稳定 ID 由 Skill slug 派生；“获取”创建一个引用该本地 Skill 的个人模板。未提供标签时返回真实空标签目录，不拿模板列表冒充标签列表。计划任务、模板变更共用本地队列，失败恢复当前集合，避免异步目录读取后覆盖并发创建。此项在服务和原页面操作通过前不记通过。

本轮验证补充：图片过滤的 Chromium 六种 HTTP 响应、读取中停止、原表单创建/回填已通过。Firefox/data/blob/本地资源的等价性没有声明通过。声音与视频分别映射；仅静音不再隐式禁止视频。模板商城本地目录和原获取流程已通过，不提供远程脚本商品或收费功能。

标签映射原来允许刷新与转发并发分配目标；现在复用原同步控制器，在映射/查找/清理边界加队列、快照核对和代次检查。未替换同步后端。原 `Browser.setColor` 仍由标准 Chrome 明确拒绝，不以 UI 值写盘伪报支持。上述修复没有删除失败断言，首次失败与后续实际重跑均保留。

Firefox 图片过滤补齐决定（实现前留痕）：实际探针确认 BiDi 暂停响应时 getData 会等待响应完成，不能用于放行前的大小判定；原生 WebExtension filterResponseData 已在 Firefox 160 对六种网络图片通过。正式实现改用该过滤器，只在设置正阈值时临时安装到该浏览器会话，保留现有代理/指纹/Worker 管线。诊断只连接每个运行窗口自己的带随机能力路径的回环端口，不访问外部服务器；启动必须收到就绪回执。滤镜有 8 MiB 单图、512 活动请求、64 MiB 总缓冲和 30 秒预算，超资源预算明确失败并报告，停止时回收端口/在途滤镜。图片响应缓存仅在正阈值会话绕过，防止旧大图直接命中缓存绕过过滤；这项性能取舍须由缓存回归验证后才能记通过。

标准 Chrome 主控配色决定（实现前留痕）：保留 Browser.setColor 的优先路径；不支持时，用该配置目录内的临时本地 Chrome 主题扩展实际改变浏览器外框/工具栏，不在网页上画假外框。已经通过真实 X11 外框像素探针证明 RGB 值改变和卸载恢复。为避免覆盖用户原主题，正式实现必须先通过 Chrome 自身主题接口读取默认/灰色/种子颜色/第三方主题，再在停止和异常恢复时还原；未验证还原前不记通过。标准 Chrome 外框为不透明表面，RGBA 的 alpha 不能冒充系统窗口透明度支持；前端颜色值与控件仍保留原产物。
