# 调度、状态响应与恢复中断保护优化

基线：`528a10a`。本轮延续安全与执行边界修复，处理任务所属环境相同时的调度阻塞、重复状态水位传输，以及浏览器数据恢复在进程退出后的保护缺口。没有新增生产依赖。

## 行为变化

| 场景 | 原行为 | 当前行为 |
| --- | --- | --- |
| 多个任务使用同一环境 | 先拿全局执行槽，再等待同环境任务；同环境任务可占满所有槽位，其他环境也无法执行 | 调度器按 key 管理等待队列，同 key 按 FIFO 执行，不同 key 轮流取得可用槽位；等待任务不计入运行数 |
| 全局仍有空槽，但单个环境积压很多任务 | 全局上限掩盖了同 key 等待；单独按 key 排队后也需要约束队列容量 | 容量检查同时考虑 key 是否可运行；等待数达到上限后拒绝继续积压，仍允许其他 key 立即使用空槽 |
| 取消尚未运行的 RPA 任务 | 只记录取消意图，等它排到前面才保存终态 | 通过排队 AbortController 直接移出队列，保存 cancelled 终态并发送事件；不等待前面的浏览器任务结束 |
| 同 key 的任务超时，但其底层工作忽略取消 | 已有全局槽位保护，新增 key 也必须遵循同一资源语义 | 调用方可超时返回，但 key 和执行槽都等实际工作结束后释放 |
| UI 的空闲状态轮询 | 响应包含整份水位表，前端实际从已加载的行重新构造水位 | 可信 IPC 使用 `includeWatermark: false`，省略重复水位；行、删除列表和 full 回退保持一致，默认 `statusDelta` 格式兼容 |
| 批量删除任务期间，后面的任务开始执行 | IPC 在循环前取得一次运行快照，等待前一项保存后仍使用旧快照 | 每次删除前按 ID 查询当前 running/queued，跳过刚开始运行或进入队列的记录；正式引擎直接查询 Map/Set，避免每项重建整份运行快照 |
| 恢复期间进程退出 | 暂存目录及映射清单保留，但新进程没有原先的维护锁 | 启动 Chromium/Firefox、数据删除和缓存清理前检查对应环境目录；未完成恢复抛出 `PROFILE_RECOVERY_REQUIRED`，保留所有恢复材料 |
| 恢复成功或回滚成功，但删除暂存目录失败 | 剩余目录无法证明恢复已结束 | 完成后写入并同步 `settled.json`，区分提交成功/回滚成功；下次使用目录时清理已结束的残留。缺失、无效和未知版本标记均按未完成处理 |

调度实现用可直接移除节点的 FIFO 队列，避免每次取消或寻找可执行任务时移动/重扫整批任务。空闲时释放 key、节点和任务引用；保持无 key 调用原有的全局 FIFO 行为。RPA 的 key 是任务所属的 `profile_id`。

## 状态响应测量

使用真实状态投影方法、环境清洗函数和可信 IPC 注册器，构造 10/100/1000 条环境记录。比较基线响应契约与新 IPC 响应，并验证前端合并结果一致。大小按 UTF-8 JSON 计算，未捕获 Electron 实际传输帧。

| 环境数 | 原空闲响应 | 新空闲响应 | 请求水位（保持原格式） | 一条变化时原响应 | 一条变化时新响应 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 382 B | 37 B | 332 B | 3,921 B | 3,575 B |
| 100 | 3,533 B | 37 B | 3,483 B | 7,075 B | 3,577 B |
| 1000 | 36,834 B | 37 B | 36,784 B | 40,379 B | 3,579 B |

1000 条环境时，空闲响应 JSON 减少约 99.9%；计入仍需传入的水位后，单次请求加响应从 73,618 B 变为 36,821 B，减少约 50%。首次全量仍需传送全部行，单行变化仍需传送变化行。本轮没有把整个轮询流程变成常数成本。

原始结果：`2026-11-11-status-payload-benchmark.json`。运行环境 Node v24.22.1；每次序列化耗时使用七组、每组 100 次的单次中位数，仅作局部成本参考，不表示真实桌面或浏览器吞吐提升。


## 恢复目录的判定与处理

新文件和映射清单先以 0600 权限写入，并执行文件同步，再改动活跃文件。暂存目录的创建与清单、结束标记的目录同步采用平台允许的尽力策略。`finish()` 只允许在全部文件已安装时结束；完整回滚也会保存结束标记。

检查发生在操作涉及的环境目录，没有在每次状态轮询中扫描整批环境。已有进程内维护锁继续协调恢复与启动、删除、缓存清理。启动检查等待文件系统时，停止操作仍能取消该次启动；检查返回后会再次核对生命周期版本。

遇到 `PROFILE_RECOVERY_REQUIRED` 时：先停止应用及受影响的浏览器，另存环境目录、恢复目录和对应的应用数据/密钥文件，再核对 `manifest.json` 中的 target/staged/backup 映射与原文件。不能仅凭没有 `.previous` 文件就认定目标原先不存在；中断可能发生在移动原文件之前。恢复文件时也要核对环境配置、代理、分组是否已部分保存，处理完成后再移出保留的恢复目录。

旧版本残留目录没有结束标记，会保守地要求检查。带有效结束标记的目录才允许自动清理；符号链接、目录联接、无效标记或未知版本不会被当作已完成。检查不会跟随恢复目录链接去删除其他位置的数据。

## 验证覆盖

- 调度自测覆盖无 key 兼容、同 key FIFO、其他环境绕过等待、满队列与空槽并存、排队取消、销毁、超时保留实际槽位，以及空闲资源释放。
- RPA 生命周期自测覆盖同环境积压时其他环境仍能完成、排队取消即时保存、任务创建期间 stop-all、真实运行结束后的清理。
- 恢复自测创建子进程，分别在暂存完成、原文件移走、新文件安装后退出，再创建全新的引擎验证 Chromium/Firefox 启动拦截、原备份保留、批量删除预检及缓存清理保护。
- 恢复自测同时覆盖成功提交/回滚后的清理失败、无效结束标记、目录联接/符号链接和文件系统检查期间取消启动。
- 状态和 IPC 自测覆盖默认响应兼容、精简 full/增量/删除响应、运行状态版本、前端合并一致，以及批量删除期间任务刚开始执行的竞争。

## 本轮边界

本轮提供恢复中断的检查与保护，没有把浏览器文件、代理库、设置与引擎数据库变成跨存储共同事务。后续保存阶段失败，前面成功写入的元数据仍可能部分生效；恢复目录中的映射用于检查与修复，应用不会据此自动猜测应完成还是回退全部元数据。断电和文件系统故障也不等价于可回滚的共同事务。

同 key 调度约束任务所属环境；流程中切换到其他环境的动作仍遵循既有执行语义。没有增加跨环境动态锁或共享 CDP 动作的全局隔离。

本地检查不含真实 Electron/浏览器、Windows/macOS 桌面验收或 Rust 编译。测量使用合成记录，不把 JSON 大小变化表述为整应用性能提升。
