## 第一轮：DNS 参数正确性与多余查询

| 问题与触发方式 | 原行为 | 修复结果 |
| --- | --- | --- |
| `lookup(host, 6, callback)` 或 `family: 'IPv6'` | 被当作默认 IPv4 查询 | 规范化数字及 `IPv4`/`IPv6` 名称参数，并拒绝非法 family |
| `family: 4` 的主机没有 A 记录但有 AAAA 记录 | 回退到 IPv6，违反调用方明确限定的地址族 | 只有默认 `family: 0` 允许 IPv6 回退；明确的 IPv4/IPv6 限定得到保留 |
| 直接传入 `127.0.0.1` 或 `::1` | 仍调用 DNS resolver，可能造成多余网络请求或失败 | 按本机 `dns.lookup` 的实际行为直接异步返回 IP，支持 `all: true` |

新增三组回归在修复前失败；修复后 DNS 检查 48/48、代理 DNS 集成检查 6/6。复核保留了已有的 IPv6-only 默认回退、系统 resolver 策略及在途请求合并行为。

## 第二轮：下载连接生命周期与跨域请求头

下载器在重定向及非成功响应中原本使用 `res.resume()` 持续读取正文。服务器如果不停发送正文，即使最终文件已下载成功或已经报告错误，原连接也可能持续占用带宽和 socket。

修复为主动销毁无用响应及其请求，并标记已废弃跳转，避免清理旧连接产生的迟到错误干扰后续跳转。成功下载仍交给原有 pipeline 处理背压、取消、字节数和摘要校验。

跨域重定向原本仅移除 Authorization/Cookie。现在同时移除 `Proxy-Authorization` 及旧 `Host`，由新目标生成正确 Host，避免将代理认证信息发送到另一个源。

新增循环发送正文的 HTTP 302/503 本地服务器用例，断言连接在 250ms 内关闭；原实现两项均失败。扩充的跨域请求头检查也在原实现失败。修复后下载器检查 43/43，包括现有断点续传、摘要、取消、错误响应和 URL 校验用例。

250ms 为本地回归的观察期限，不是生产网络性能承诺。

## 第三轮：RPA 变量隔离和特殊名称

开始节点的 `globalVariable` / `config.variableObjList` 默认值原本直接放入任务变量。任务共享同一个已解析模板时，嵌套对象和数组也被共享，一个任务的修改可以影响另一个任务和原始模板。

现在默认值与显式任务变量一样按任务深复制，保留显式变量的优先级。变量字典改为无原型对象，使 `__proto__`、`constructor` 等名称成为普通变量；没有初始变量的直接步骤执行也创建同样的字典。插值与条件读取仅接受自身字段，避免把缺失的变量解释成 Object.prototype 成员。

回归覆盖：两个任务修改嵌套变量互不影响；模板保持原值；特殊变量名保留；显式值覆盖默认值；未定义的原型名称不参与插值；真实文件步骤把 CSV 写入 `__proto__` 变量时不改变字典原型。

修复后变量、文件步骤、任务生命周期检查通过。对外结果仍由原有 `snapshotVariables` 输出可序列化的普通对象。

## 第四轮：CSV 数据正确性与导出性能

原导出器按 `record[field]` 读取字段。指定不存在的 `constructor` / `toString` / `__proto__` 列时，会把继承成员错误地写成 `undefined` 或 `{}`。现在只读取记录自身字段，缺失列为空；实际存在的同名字段仍正常导出。

同时减少导出计算中的分配：

- 直接遍历记录和字段，移除每行的临时 `fields.map()` 数组和嵌套生成器。
- 不含双引号的单元格直接包装，省去不必要的正则替换。
- 保留按块输出、转义、Unicode、换行、取消及文件原子替换行为。

可复现命令：

```bash
cd Browserapp
node scripts/benchmark-csv-export.js bd9a694c852bae7dfccf299e0e8417ab0880c937
```

| 数据规模 | 修改前耗时中位数 | 修改后耗时中位数 | 耗时减少 | 输出验证 |
| --- | ---: | ---: | ---: | --- |
| 100,000 行 × 8 列，16.91 MB | 123.82 ms | 111.97 ms | 9.57% | 字节数、SHA-256 相同 |
| 20,000 行 × 64 列，26.65 MB | 202.60 ms | 180.51 ms | 10.91% | 字节数、SHA-256 相同 |

每组在隔离 Node 进程预热后采样七次。数据包含中文、emoji、逗号、双引号和 CRLF。此处只测 CSV chunk 生成，不包括浏览器、GUI 或文件系统写入；不能据此宣称整应用提速。结束时 heapUsed 不是内存峰值，也没有证明所有场景内存都下降。

## 第五轮：复核发现的回调错误边界

回看 DNS 调用链时发现：resolver 的 Promise 链直接调用消费方回调。回调抛出的错误会进入 DNS 的 catch 分支；当错误带 `ENODATA` 时甚至会触发系统解析并第二次调用回调。

现在回调在独立微任务中交付，将消费方异常与解析失败分开。独立进程回归主动让回调抛出带 `ENODATA` 的异常，确认异常向外传播一次、回调仅调用一次、系统回退次数为零。该回归在修复前失败；修复后 DNS 检查 49/49。
