# 性能、代码分类与可维护性审查

日期：2026-11-10（用户所在时区）。基线：`main` / `0c06ae8`。本报告记录本次工作区改动和本次实际执行的检查；之前开发报告中的测试结果未计入本轮结果。

## 范围与结论

项目仍有可优化空间。本轮检查了目录与依赖、宿主/IPC、UI 列表、引擎和扩展、持久化、任务调度、代理/CDP、指纹入口、Rust 代理与现有 CI。初始源码清单在排除内核、资源、依赖和构建目录后包含 406 个 JavaScript 文件、41 个 Rust 文件，包含生产代码和检查脚本。

审查采用架构梳理、重点调用链阅读、静态检查、故障用例和局部性能测量。它不等同于逐行证明全部源码正确，真实桌面、多平台和浏览器负载仍需要单独验收。

项目已有状态缓存、列表行复用、分页、SQLite 差异保存、代理连接复用和合并写入。本轮继续优化实际重复工作，并补齐与这些路径相关的行为边界。

代码职责与修改入口已整理到 [代码分类与维护入口](../code-organization.md)。

## 可重复性能测量

命令：在 `Browserapp/` 执行 `node scripts/benchmark-review.js 0c06ae8`。

环境：Linux 容器、Node v24.22.1；1,000 个环境。每条路径预热 30 次，之后取 9 组中位数，每组 30 次调用。基准从 Git 读取指定基线函数，与工作区实现比较，并先断言返回数据一致。原始结果见 [基准结果 JSON](2026-11-10-performance-benchmark.json)。

| CPU 路径 | 优化前，每次 | 优化后，每次 | 本次测量倍率 |
| --- | ---: | ---: | ---: |
| 空搜索 | 1.6692 ms | 0.0304 ms | 54.89× |
| 日期排序 | 10.3139 ms | 0.5522 ms | 18.68× |
| 字段搜索 | 1.8907 ms | 0.4010 ms | 4.72× |
| 扩展统计，100 个扩展、每环境分配 3 个 | 4.2286 ms | 0.1289 ms | 32.79× |

更稳定的操作数量：1,000 个环境的空搜索从 2,000 次编号/分组显示投影降至 0；100 个调度排空等待者最初创建的 5ms 轮询定时器从 100 个降至 0。批量删除从每个环境一次数据库事务变为整批一次。

时间会随负载、JIT 和 GC 变化。测量只涵盖这些 CPU 路径，不含真实浏览器、DOM、IPC、加密或磁盘，因此不能推算整应用启动、总内存或总吞吐有相同倍率收益。反向扩展索引的收益取决于分配稀疏度；全部环境启用全部扩展时，输出关系本身就有 P×E 个元素。
