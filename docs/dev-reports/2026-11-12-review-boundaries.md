# 2026-11-12 深度审查与四轮优化

起点：`main` / `a8d7ebe`。本次结论来自当前源码、实际复现、专项回归和本轮聚合运行；历史报告仅用作定位入口。改动保留在当前工作区。

## 项目结构与判断

OpenBrowser 1.0.27 是本地多浏览器环境管理应用，主要生产路径仍在 Electron / Node 中。每个环境具有独立浏览器数据目录、代理与指纹配置；宿主管理生命周期，UI 通过预加载桥和 IPC 读取状态、提交命令。HTTP API、MCP 和 RPA 复用引擎能力。Rust 代理桥受环境变量门控，不能把 Rust 库中所有模块视为默认生产路径。

| 层次 | 主要入口 | 本轮阅读和验证重点 |
| --- | --- | --- |
| 桌面与 UI | `main.js`、`main/profile-ipc.js`、`renderer.js`、`ui/` | 首次加载、状态合并、代理检查调用方、编辑版本语义 |
| 环境引擎 | `engine/profile-proxy.js`、`profile-revisions.js`、`profile-maintenance.js`、`profile-sync.js`、`session-api.js` | 网络等待后的写入、删除与恢复并发、会话查询合并 |
| 持久化 | `engine/persistence.js`、`state-storage.js`、`automation/local-settings.js`、`coalesced-writer.js` | 单次写入屏障、失败重试、退出排空、加密与原子替换 |
| 自动化与控制面 | `automation/task-scheduler.js`、`task-queue.js`、`rpa/`、`api/` | 并发槽位、取消、任务图预算、文件边界、接口输入 |
| 网络 | `network/{cdp,bidi}-connection.js`、`http-request.js`、`proxy-forwarder.js`、`engine/proxy-probe-runner.js` | 协议异常、共享连接故障隔离、定时器清理、代理验证证据 |
| 云与恢复 | `automation/cloud/{profile-data,file-restore}.js` | 有界读取、恢复暂存与维护占用；代理写入也必须遵守维护保护 |
| 原生与 CI | `crates/openbrowser-core`、`.github/workflows/ci.yml` | 阅读桥接、连接池、锁及门控说明；确认验证条件与本环境限制 |

项目已经具有状态增量、连接复用、差异保存和大量回归测试。当前值得优先解决的问题集中在异步操作之间的边界：各模块单独正确，并不保证等待期间的环境仍是原来的版本，也不保证历史网络证据属于当前线路。本轮据此进行四轮修改，每轮运行相关专项，末轮再运行完整注册集合。

## 第一轮：保存与批量队列

| 问题 | 影响 | 处理与复核 |
| --- | --- | --- |
| 写入器计算的指数退避，被 DeferredQueue 失败路径重新设置为基础延迟 | 磁盘持续不可写时，重试频率无法降低 | 队列在重新入队后读取写入器的退避策略；新保存请求也沿用当前退避。成功和无需写入时恢复正常延迟。零延迟配置的失败重试至少等待 1 ms |
| 每次保存请求都添加一个相同的待写标记 | 一次批量保存产生与调用数等量的冗余队列元素 | 合并同一待写批次的标记；每个调用方仍有自己的完成或失败通知 |
| `addAll()` 将整个数组展开为函数参数 | 大批量输入触发 RangeError，未能入队 | 按元素追加；固定读取原数组长度，兼容把队列自身作为输入 |

`coalesced-writer-selftest.js` 24 项通过。新增检查覆盖实际重试定时器、上限、恢复、零延迟、10,000 个请求的完成通知、200,000 项入队和自身追加。既有并发写入、失败传播、退出排空及跳过未变化状态检查继续通过。

## 第二轮：代理操作的并发和资源生命周期

| 问题 | 影响 | 处理与复核 |
| --- | --- | --- |
| 检查代理后把等待前的完整环境写回 | 检查期间的编辑被覆盖，删除的环境可能重新出现 | 进入操作时记录环境版本，提交前检查版本及维护占用；使用项目既有 `PROFILE_STALE_REV` 和 `PROFILE_MAINTENANCE` 错误 |
| 动态提取代理的网络等待后缺少同样保护 | 删除或恢复过程中仍可能写入旧环境 | 刷新和提取完成后分别复核，版本异常不作为普通提取失败吞掉 |
| 探测合并键漏掉备用节点、提取 URL、回退信息和验证状态 | 不同请求错误共享同一个在途结果 | 在固定字段键中加入改变探测语义的输入；等价请求仍复用在途工作 |
| 探测完成后清理了 `slot.timer`，实际定时器是闭包内的 `timer` | 快速成功和快速失败均留下期限定时器；迟到回调继续执行清理 | 清理实际定时器，增加一次性结算保护 |

新增 `proxy-operation-race-selftest.js` 并加入 SUITE。覆盖编辑、删除、同 ID 重建、维护开始前后、内容相同的重写、请求合并及真实本地 HTTP 提取竞争。既有代理功能、预算和韧性专项通过。

## 第三轮：共享通信与界面一致性

| 问题 | 影响 | 处理与复核 |
| --- | --- | --- |
| BiDi 收到合法 JSON `null` 后直接读取属性 | 消息处理函数抛出异常 | 在解析后验证消息信封类型；忽略空值、标量、数组和非法 JSON |
| CDP / BiDi 把 JSON 序列化错误当成 socket 故障 | 单条含循环结构或 BigInt 的命令关闭共享连接，连带拒绝其他正常命令 | 在注册待完成命令和定时器前完成序列化；坏参数只拒绝本条命令，实际发送错误仍关闭故障连接 |
| UI 只在出口 IP 为真值时合并状态 | 引擎明确清空 IP 后，启动合并和轮询仍显示旧出口 | 区分字段缺失与明确清空；保持未变化记录的引用、支持 null 坐标和零值 |

新增 `transport-isolation-selftest.js` 并加入 SUITE，8 项通过；CDP 生命周期、Firefox 初始化屏障和 UI 状态存储专项也通过。检查包含一个正常命令在另一个命令序列化失败后继续完成，以及后续命令仍可使用同一连接。

## 第四轮：代理验证证据的归属

沿上一轮的请求合并边界继续追踪发现：`_testProxy()` 不论实际选择了哪一条代理，都把同一环境此前的 `networkInfo` 和出口信息传给探测器。备用节点、强制代理或动态提取改变地址或账号后，旧线路的验证标记仍可能进入新线路的降级路径。

现在使用代理协议、端点和账号身份判断历史证据是否适用。实际探测路线与已知身份一致时保留原有降级行为；身份改变时不提供旧验证和地理数据。动态提取改变代理身份时清除旧网络记录。新增检查验证原线路继续复用、不同账号不继承、提取的新地址不继承。该专项最终 12 项通过；既有代理韧性 13 项通过。

这部分新增检查使用真实生产模块和注入的探测适配器观察传递参数；真实代理网络协议行为另由既有本地 HTTP / SOCKS 专项验证。没有把适配器检查描述为真实外部代理验收。
