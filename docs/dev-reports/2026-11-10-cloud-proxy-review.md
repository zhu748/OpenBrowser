日期：2026-11-10。代码基线：`0e66932`。本次在现有模块化基础上复核应用结构、主要调用边界及既有检查；修改集中在已确认的云同步和代理分配路径。没有新增生产依赖，也没有把模块迁移的行数当作功能删除。

## 确认并处理的问题

| 问题 | 调整及效果 |
| --- | --- |
| 每个代理重新遍历全部环境，并重复解析代理文本 | 每次统计建立关联 ID、原始字符串和协议端点索引。计算量由代理数 × 环境数，变成代理数 + 环境数 + 实际匹配输出数；不跨快照缓存，允许原地编辑后立即生效。 |
| 云配置合并中的统计重复扫描另一侧数组 | 使用 ID Set 处理覆盖统计和本地保留项；单环境批量推送也建立 ID Map，保留第一条匹配的原行为。 |
| 首次云备份/恢复使用同步 scrypt | 包流程改用异步 KDF，并合并同一密钥的在途计算。保留原同步导出、OBE1 格式、新旧成本的解密兼容和独立随机 IV。 |
| 本地优先/本地较新仍被远端浏览器文件覆盖 | 合并内部返回远端来源集合，恢复文件遵循同一选择；公开 mergeProfiles 返回结构不变。 |
| 恢复代理库落盘失败被吞掉 | 失败上抛，调用方不会再收到虚假的整体成功。 |
| 重复远端 ID 让配置与文件来源不明确 | 整批校验中拒绝重复 ID；写入文件前检查全部选中环境的运行、启动、停止状态。 |
| 剩余浏览器备份额度为零时回退到 80 MB | 用空值默认处理零额度，按实际解码字节累计，统一写入/恢复上限。 |
| 文件 stat 后增长可突破读取预算 | 限制真实读取字节；备份文件数与恢复端同为最多 2,000 个/环境；最终生成包也检查 100 MB 上限。 |
| 云提供商重复实现 HTTP 读取，只有 socket 空闲超时 | 复用 network/http-request.js，覆盖总期限、提前断流、响应限额和连接清理；保留提供商的手动重定向策略。 |

## 后续重点和当前边界

1. **恢复事务与生命周期**：文件、代理库、设置、引擎保存仍分阶段执行；失败会报告，但不承诺整体回滚。运行状态检查也不等同于启动/恢复共用的原子锁，应后续统一生命周期调度。
2. **覆盖语义**：mergeProfiles 的 overwrite/remote-wins 输出远端列表，但引擎 syncProfiles 明确保留输入外的本地记录。因此当前恢复不能被解释为已经删除所有本地独有环境。涉及数据删除的产品行为应先明确定义再实施。
3. **渲染端状态**：renderer.js 仍有 4,829 行并与 classic script 共享全局状态。可继续沿现有编辑控制器拆出会话同步与事件接线，并配合真实桌面验证。
4. **大型模块**：live-sync-v5.js（2,401 行）、browser-kernel.js（2,206 行）和 rpa-engine.js（1,869 行）仍承担较多编排工作，后续优先按资源生命周期边界拆分，避免仅为缩短文件增加间接调用。
5. **大包主线程开销**：JSON 编解码和 AES 操作仍在主线程；本轮仅把 KDF 异步化。进一步降低大包峰值内存和卡顿，需要流式包格式或完整 Worker 管线及兼容性设计。
6. **平台验证**：本轮未修改 Rust；环境无 Cargo，未编译或运行 Rust 测试。未运行真实 Electron/Chromium、多实例负载及 Windows/macOS 原生端到端检查。现有纯 Node 通过不替代这些验证。
