# 第三轮：RPA 生命周期、容量回收与扩展 IPC

日期：2026-11-10。起点是第二轮结束时的工作区；Git 基础提交仍为 `0c06ae8`，三轮改动尚未提交。本报告记录本轮新增工作。

## 已复现与修复

| 问题 | 原行为与证据 | 修复与回归 |
| --- | --- | --- |
| RPA 同一环境可能重复启动入队 | `ensureProfileRunning()` 在设置共享 Promise 前等待日志。两个带异步日志的并发调用实测触发 2 次启动 | 先发布共享 Promise，再调用日志和启动队列；20 个并发调用只启动一次，失败后队列可恢复 |
| 任务初始化失败后残留运行状态 | 初始化阶段的存储更新位于 try/finally 外。注入存储失败后，实测 `running.has(taskId)` 仍为 true | 初始化状态更新、事件和诊断统一进入清理保护；初始化失败也清除运行/取消标记 |
| 排队任务取消后仍执行 | 旧停止逻辑只识别运行任务，而任务实际开始时又清除取消标记 | 分别追踪排队与运行任务；排队取消保留到执行入口，先检查取消再启动浏览器；取消单个任务不影响其他排队任务 |
| 全部停止漏掉尚在创建记录的计划 | 任务记录创建需要 await，停止时尚无运行任务可枚举 | 计划创建前记录停止代次；全部停止后才创建完的同批任务按取消处理，随后新提交的计划仍可执行 |
| 最后一个步骤内的取消可能报告成功 | 取消检查仅在每一步开始时执行 | 步骤循环完成后再次检查取消和任务截止时间，再提交成功结果 |
| RPA 超限回收重复序列化 | `fits()` 每调用一次就重新序列化全部剩余任务，循环内多次调用，回收旧记录还逐项 splice | 独立 `rpa-store-budget.js` 缓存任务尺寸、维护剩余字节数，批量移除，按固定顺序回收日志/结果 |
| 容量估计与文件格式不一致 | 预算使用紧凑 JSON，文件写入使用缩进 JSON；删除记录后旧估计仍包含已删除逗号开销 | 私有存储改写紧凑 JSON，字段内容保持一致；预算精确扣除数组逗号，覆盖中文 UTF-8、精确边界和实际文件大小 |
| 扩展重启可能尝试启动退出未确认的环境 | 旧批量助手只要 stop 的 Promise 成功就加入重启集合 | 检查 running/cleanupBlocked 和当前运行表；退出未确认、停止失败、正在启动或元数据已移除的环境不会重启 |

扩展的七个 IPC 通道已提取到 `main/extensions-ipc.js`。宿主继续通过 `registerTrustedIpc` 挂载，事件来源校验由主进程统一执行。模块通过参数接收依赖，离线检查可覆盖真实处理函数，无需导入 Electron 主进程。

批量停止/启动仍分别限制为 4/3 个并发；单个环境失败不会阻断其他成功项。扩展商店直连失败后的系统代理回退路径也保留并经过检查。

## RPA 接口行为

- `getStatus()` 保留 `running` 与 `count`，新增 `queued` 和 `queuedCount`。
- 停止单个排队任务返回 `cancelling`；任务进入执行入口后持久化为 `cancelled`，不会启动该任务的浏览器。
- 全部停止的返回 `count` 包含本次请求取消的运行与排队任务。计划还在创建记录时，停止代次保证这些记录创建完成后也被取消。
- 未知任务 ID 返回 `not-running`，不再累积无效取消标记。
- 对已开始的操作采用协作式取消。网络请求和已进入浏览器启动链的底层操作没有新增强制中断能力；本轮不能据此宣称所有操作都可立即停止。

## 性能测量

命令：在 `Browserapp/` 下执行 `node scripts/benchmark-rpa-budget.js 0c06ae8`。基准从 Git 提取原预算函数，与当前独立策略比较。1,000 条任务，原始紧凑 JSON 为 375,951 字节，配额 93,987 字节；1 次预热后取 5 次中位数。Node v24.22.1，内存中的 CPU 路径，不包含文件系统、浏览器和网络。

| 指标 | 原实现 | 新实现 |
| --- | ---: | ---: |
| 回收耗时 | 608.9905 ms | 3.5265 ms |
| JSON 序列化调用 | 471,121 | 1,001 |
| 保留任务 | 248 | 250 |
| 最终紧凑 JSON 字节 | 93,199 | 93,951 |

两种结果均符合配额；新实现按实际逗号字节核算，保留了原实现额外回收的两条记录。调用数量比宿主相关耗时更适合复核复杂度变化。原始数据见 [基准 JSON](2026-11-10-round3-rpa-budget-benchmark.json)。

同一原始样例的缩进 JSON 为 492,975 字节，紧凑 JSON 为 375,951 字节。这是该样例的格式体积对比，不能据此推断整应用或任意任务文件的固定比例收益。

容量是有保留条件的预算：如果计划/模板、最新任务或受保护的运行任务本身已超出配额，回收器保留它们，不能保证强行压到配额以下。新检查分别覆盖可回收历史和受保护记录。
