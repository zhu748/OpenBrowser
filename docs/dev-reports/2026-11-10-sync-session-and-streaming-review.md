# 下一轮：同步会话、扩展边界与流式输入

日期：2026-11-10。接续上一轮未提交的修改，仓库 HEAD 仍为 `c1c02c6`。本轮重点复核 UI 会话选择、窗口同步异步生命周期、扩展身份与分配，以及文件导入路径。

## 发现与改动

| 问题 | 影响 | 本轮改动 |
| --- | --- | --- |
| 会话刷新在 await IPC 前复制选择 | 用户等待期间刚改变的勾选会被旧选择覆盖 | 提交响应时读取当前选择和同步状态；提取 ui-session-controller，保留首次全选和主环境顺序 |
| 迟到的刷新调用返回旧 Promise | 调用方 await 返回后，自己请求的后续刷新还没完成 | 一个活动请求和一个共享后续请求；迟到调用等待后续 IPC，失败后也能继续刷新 |
| 空扩展白名单放行全部页面 | 未分配的密码管理器等扩展也可能被捕获和镜像 | 空白名单拒绝全部页面；授权仅来自当前分配路径，loadedExtensions 仅用于查找对应路径的实际 ID |
| 撤销分配后旧连接保留 | 页面仍存活时继续捕获扩展输入 | 每次扩展刷新先关闭不再获准的连接并移除映射，即使浏览器仍报告该页面存在 |
| manifest.key 身份推导错误 | 原代码直接哈希 base64 文本，且使用十六进制字母；与 Chromium 扩展 ID 不匹配 | 使用既有 CRX 公钥 ID 工具，对解码后的字节取摘要并映射 a–p；无 key 时按 Chromium 原生路径字节推导身份 |
| 清单缓存只比较 mtime | 保留 mtime 的文件替换可能留下旧身份，旧路径也一直留在 Map | 比较 mtime/ctime/size/inode；移除分配和停止同步时回收缓存 |
| 扩展映射重复构造 used 集合和候选数组 | 多扩展页面时反复扫描所有映射与目标 | 每次刷新按从环境建立 ID、完整页面路径、扩展 host 和占用索引；路径大小写继续区分 |
| stop() 未持有正在 open 的连接 | 停止或重启后旧握手可能发布新 Map 条目、继续注入 | 跟踪在途握手，停止时立即关闭；恢复时检查代次、主环境引用及连接归属；迟到打开不再发布或注入 |
| CSV/文本完整读取、完整切行 | 占用源文件副本，解析期间较长时间不能响应取消 | 64 KiB 流式读取；CSV 解析状态跨块保存，按片段拼接字段；文本逐行收集并避免超长行反复扫描 |
| 取消与 optional 导入混用 | 取消不能作为普通坏输入跳过，更不能发布半份结果 | 每块和完成时检查任务状态，完成后才赋值；取消始终终止任务，旧变量保持不变 |
| CDP 收到 JSON null | JSON 解析成功后访问 value.id 会抛错 | 长连接及专用连接忽略非对象协议帧，不影响正常待处理命令 |

扩展 ID 规则核对了 Chromium 的 [id_util.cc](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/crx_file/id_util.cc)：公钥字节的 SHA-256 前 16 字节映射为 a–p；路径身份使用原生路径字节，Windows 盘符转大写、路径按 UTF-16 编码。Windows/Linux 的固定输入向量已纳入离线检查，尚未替代真实浏览器加载验证。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| ui/ui-session-controller.js | 会话选择、主环境与刷新 Promise 的状态逻辑，无 DOM 和宿主全局依赖 |
| automation/sync/extension-pages.js | 分配许可、身份与缓存、扩展目标映射、捕获连接及扩展事件处理；由宿主显式传入注入文本 |
| automation/rpa/csv.js | 可分块写入的纯 CSV 状态机、记录收集及编码；原 parseCsvRecords 入口保留 |
| automation/rpa/file-input.js | UTF-8 文件流、CSV/文本读取和取消检查，无浏览器依赖 |

live-sync-v5.js 从 2,401 行降至 2,240 行，扩展领域代码不再混在平台窗口与全屏同步中。renderer.js 保留 DOM 绑定，刷新竞争逻辑通过显式回调传入控制器；此次重点是职责和可测试性，界面入口总规模仍约 4,800 行。

## 性能测量

```bash
cd Browserapp
node scripts/benchmark-sync-import.js c1c02c6
```

完整结果见 [测量 JSON](2026-11-10-sync-session-streaming-benchmark.json)。计时在独立进程中运行；目标 ID 访问次数在额外的一次执行中统计，避免 getter 探针改变计时结果。扩展基准注入同样的白名单和空连接动作，仅测映射计算，不含权限查询、真实连接和桌面渲染。

| 场景 | 基线 | 修改后 | 范围 |
| --- | ---: | ---: | --- |
| 主/从浏览器各 1,000 个扩展页面，映射中位耗时 | 63.6 ms | 4.5 ms | 5 个预热后样本，局部耗时降低约 93% |
| 一次映射目标 ID 读取次数 | 1,503,500 | 7,000 | 独立探针执行，说明重复扫描显著减少 |
| 50,000 行、6,927,805 字节 CSV 导入 | 120.2 ms | 103.0 ms | 3 个预热后样本；总耗时存在波动，不承诺固定吞吐收益 |
| CSV 导入期间最大定时器采样间隔的中位数 | 109.1 ms | 5.7 ms | 1ms 定时器并在完成时补采样；包括调度延迟，不是精确 CPU 阻塞时间 |
| 导入采样堆增量中位数 | 56.0 MiB | 52.7 MiB | 包含完整结果，内存仍以保留的记录为主，不是 RSS 或精确峰值 |

CSV 基准的新旧记录 JSON 摘要一致：`b9e19e948b4c35924b1dbffdd9b206501ec650e18b9216821489837bd8705036`。CSV 基准相对原始 HEAD，因此包含连续两轮的输入解析调整，不能视为相对上一轮工作区的独立收益。

## 尚未覆盖的边界

- 流式读取减少源文件副本和单次阻塞，但 CSV/文本的最终记录仍完整留在变量中；单个巨大字段和 JSON 文档也仍需完整驻留内存。尚未引入任意文件或记录上限。
- 未进行真实扩展加载、跨平台桌面或大量浏览器同步的端到端测量，算法测试和假连接不能替代这些检查。
- 当前无 Cargo，Rust stdout 无界队列的遗留风险仍需在具备工具链的环境中验证；本轮未改 Rust。
- renderer.js 的其余扩展/环境/DOM 交互，以及 live-sync-v5.js 中的平台原生驱动和全屏领域仍可继续建立更明确的模块边界。
