# 模块分类、数据校验与维护性优化

基线：main / `9ae738a`。本轮调整 JavaScript 应用层，保留既有 HTTP 路径、IPC 频道、引擎入口和内核管理公开导出。

## 行为修复

1. **坐标一致性**：新增浏览器和 Node 共用的 `shared/profile-values.js`。界面、API、Profile 清洗和 Persona 构建使用同一份数值与成对坐标校验。空值、布尔值、非有限数及越界坐标不再变成有效地理位置。自定义位置无效时不借用出口位置；合法零坐标保留。
2. **真实 CDP 地址**：列表与其他 API 一样读取 `/json/version` 的浏览器 GUID。每个 API 实例最多并发 8 项；相同运行对象和端口的重叠查询共享 Promise，完成后移除，不缓存过期 GUID。查询前后检查运行对象，退出和重启后的旧结果返回 null。
3. **真实 HTTP 期限**：浏览器地址解析的每次 600ms 尝试通过 CDP HTTP 传输执行；超时销毁请求后再重试，不再用外层 Promise.race 提前释放逻辑请求、留下真实连接。
4. **RPA 能力声明**：四个原先只有日志的动作 `keyCombination`、`applySubProcess`、`getCaptcha`、`closeOtherPage` 标记为已知不支持，在执行前明确拒绝。HTTP 和 IPC 的临时步骤都先校验再创建任务；商店展示继续保留未实现动作信息。125 个现有内置/目录模版没有引用这四个动作。
5. **保存责任**：创建和复制环境只等待 `syncProfiles()` 自带的保存屏障，去掉其后的重复 persist。直接修改引擎 Map 的更新入口仍负责保存。
6. **编辑并发**：保存控制器在开始时固定编辑会话。将代理写入库后，关联命令使用第一次编辑保存返回的版本；后台刷新不能给旧草稿提供新版本。请求完成也不能关闭另一个环境的编辑器。

## 模块边界

| 领域 | 新入口 | 边界 |
| --- | --- | --- |
| 公共数值 | `Browserapp/shared/profile-values.js` | 无 DOM、Node 或 Electron 依赖的规则 |
| API 输入/输出 | `automation/api/input.js`、`profile-ids.js`、`responses.js` | 字段别名、选择解析、响应封装与脱敏 |
| API 处理器 | `automation/api/*-routes.js`、`controllers.js` | 五个领域控制器，各自声明依赖；实例构造时验证路由完整性 |
| CDP 地址查询 | `automation/api/devtools.js` | 真实 GUID、在途合并、并发和实例有效性 |
| 启动参数 | `engine/launch-arguments.js` | 参数策略通过明确输入构建；资源生命周期留在启动编排 |
| 内核发现 | `automation/kernel/discovery.js` | 文件树、平台目录、种子版本；复用打包浏览器根目录查找 |
| 自动化 IPC | `main/automation-ipc.js` | 22 个频道通过宿主注入的可信入口注册，服务与窗口由 getter 获取 |
| 编辑保存 | `ui/ui-profile-commands.js` | 接收状态访问与发布回调，可直接在 Node 中验证并发行为 |

## 实际兼容性与验证边界

- 依赖上述四个未实现 RPA 动作的外部计划现在会明确失败，需要改用已实现动作或补充执行器。
- 缺少或非法的坐标现在保持未知；API 显式传入非法 `geolocation` 时返回 400，不再保存伪造位置。
- 正确解析列表 CDP 地址需要访问真实 CDP 端口；大量不可达端口会有受并发限制及重试期限约束的排队时间。
- 当前环境未安装 Cargo，未运行 Rust 编译及测试；未进行真实 Electron、内核和跨平台桌面端到端验证。Node 模拟检查不能替代这些检查。
- `renderer.js` 的其他共享全局变量、引擎现有 prototype mixin 和大型注入脚本仍存在。后续可沿已建立的控制器和纯函数接口继续迁移，需要配合真实桌面与内核回归。
