# 通信、RPA 文件处理与响应边界复审

日期：2026-11-10。基线：`c1c02c6`。运行环境：Linux、Node v24.22.1。

后续进展：本报告遗留的扩展同步边界及 CSV/文本全量读取已在 [下一轮复审](2026-11-10-sync-session-and-streaming-review.md) 中继续处理；以下测量与规模保留为本轮历史记录。

## 审查范围与结论

项目已具备按领域拆分的引擎、IPC、API 控制器和无内核自测，适合继续在现有模块边界内优化。本轮以运行入口、状态刷新、并发连接、文件处理、持久化和对外响应为重点完成源码复核，并落实下表中的问题。此记录不代表全部 18 万余行 JavaScript 均已逐行审计。

| 路径 | 发现与处置 | 验证依据 |
| --- | --- | --- |
| CDP 握手和关闭 | `close()` 在握手完成前执行，原实现未立即拒绝 open Promise，需要等原超时；发送失败会清空 socket 引用却不关闭物理连接。改为统一结算握手和命令，再关闭连接 | 新增回归先在原实现复现失败；修复后握手取消当轮结算、发送异常关闭连接、迟到事件不再派发 |
| CDP 重复实现 | `cdp.js` 与窗口同步的 `PersistentCdp` 分别实现连接生命周期。共用 `network/cdp-connection.js`，同步入口仅保留构造参数和 8s/7s 的超时默认值；并发或重复 open 复用同一连接 | 连接池 13 项检查、同步兼容测试、背压/设置/标签映射检查 |
| RPA CSV 一致性 | 导出支持带换行的单元格，导入按文本行 split，导致列错位和记录拆分。使用完整 CSV 状态机，处理引号内 CR/LF、转义引号、BOM、空单元格及未闭合引号 | 通过公开 executeStep 进行真实文件导出→导入；覆盖中文、emoji、引号内空白行和空格 |
| RPA 导出内存 | 原导出先生成全量二维数组，再生成每行字符串，最后 join 完整文件。改为分批编码和异步文件写入，并以 Set 逐行收集列名 | 5 万条记录基准输出 SHA-256 与原实现相同；写入边界的采样堆增量明显降低 |
| 导出取消与失败 | 写入临时文件，成功关闭后 rename；每个写入批次和提交前检查取消。失败不替换旧目标，临时文件最终清理 | 中途取消、循环对象序列化失败均保留原文件；多批次真实写入结果一致 |
| RPA 职责 | 提取文件动作到 `rpa/file-steps.js`，纯 CSV 规则到 `rpa/csv.js`；挂载前检查成员冲突，继续使用原动作注册表 | 现有自动化及图形边界自测、新文件动作自测、发布依赖闭包检查 |
| 状态刷新分配 | 主进程和 UI 在每次空闲刷新时重复构造全部 ID→版本索引。按快照引用缓存并冻结索引，快照变化时重建 | 运行、端口、扩展、删除、重启、编辑竞争检查通过；原有 onRows 调用语义保留 |
| API 嵌套凭据 | 原脱敏仅处理主账号字段，遗漏 platform.accounts 的密码/2FA 及 proxyMeta.backupProxies 中的代理登录信息。按账号复用脱敏函数，复制嵌套容器，保留源数据 | 实际 LocalApiServer 路由验证更新、详情响应不含测试凭据，引擎原始凭据仍完整 |
| 环境复制 | 虽清空主账号，原复制入口仍继承多账号行。复制时将 accounts 置空 | 真实 BrowserEngine 的复制路由回归检查 |

以下路径也进行了结构和关键逻辑复核：`main/` IPC 分组、`engine/persistence.js` 与合并写入器、TrackedProfileMap/SQLite 差异保存、会话查询有界调度、API 路由注册表和 DevTools 查询、DoH 在途合并及缓存、HTTP 响应限额、代理握手缓冲上限、发布资源清单、Rust 桥及池化状态结构。本轮未改动这些路径中已有的事务、并发上限或代理选择策略。

## 性能测量

复现命令（在 Browserapp 下）：

```bash
node scripts/benchmark-review-hotpaths.js c1c02c6
```

完整采样见 [基准 JSON](2026-11-10-cdp-rpa-benchmark.json)。新旧实现分别在独立进程运行；状态用 5 轮预热后的样本取中位数，CSV 用 3 轮预热后的样本取中位数。

| 场景 | 修改前 | 修改后 | 解释 |
| --- | ---: | ---: | --- |
| 10,000 环境，200 次空闲状态计算（主进程索引及 UI 索引） | 829.2 ms | 253.2 ms | 局部耗时降低约 69%；仍需逐行比较版本，复杂度仍为 O(N) |
| 50,000 行 CSV 文件导出 | 79.4 ms | 75.7 ms | 耗时样本有重叠，不据此承诺吞吐提升 |
| CSV 写入边界采样的额外 JS 堆占用中位数 | 36.8 MiB | 15.5 MiB | 约降低 58%；不包含预先创建的输入记录，不是精确峰值或 RSS 上界 |
| CSV 产物字节数 | 6,977,805 | 6,977,805 | SHA-256 均为 `479de7d6c27fcdbfd6a7e082076faf4d4e50aa1a90336d1b247361d188a7a42c` |

状态基准不包含 Electron IPC 序列化、界面渲染和真实浏览器负载。CSV 编码批次一般控制在 64 Ki 个字符左右，但单个大单元格可能超过批次目标，输入记录本身仍驻留内存。

## 仍可继续优化的方向

1. `renderer.js` 仍约 4,800 行，多个 classic script 共享全局状态。下一步应按环境、同步、扩展控制器逐步建立显式依赖与状态入口，再拆除对应 ambient globals；现有 DOM 和生命周期检查必须同步覆盖。
2. `live-sync-v5.js` 仍约 2,400 行，包含注入源码、平台窗口驱动和同步调度。长连接已统一；可继续提取平台驱动及纯事件策略，避免改动注入片段的共享词法作用域。
3. CSV/JSON/文本导入目前仍全量读入，超大文件可能占用较多内存。应结合实际允许的数据规模确定输入字节/记录上限，再实现流式导入；上限涉及现有任务兼容，当前未任意添加。
4. Rust 主进程 stdout 使用无界 channel 避免阻塞 Tokio，但父进程持续不读时仍存在队列增长空间。后续需在有工具链的环境区分终态回复与可合并的状态遥测，并做阻塞管道和退出顺序验证。
5. 桌面性能需在目标系统记录多环境启动、同步输入、渲染延迟、RSS 和事件循环延迟。当前局部基准能证明索引分配与导出副本开销的改善，不能替代这些负载测量。
